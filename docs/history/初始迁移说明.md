## 部署交接

由部署人员完成以下操作；日常维护者继续使用后台编辑和发布。

1. 使用 Node.js 24 或本包 Dockerfile。将 `.env.example` 复制为私有 `.env`，填入最终域名与独立生成的 AUTH_SECRET、BOOTSTRAP_TOKEN。
2. 使用 `compose.yaml`，只通过 Caddy 暴露 80/443，应用和资料目录放在持久卷中。配置好域名后 Caddy 自动申请 HTTPS 证书。
3. 正式切换前，从原站主管理员权限导出最新完整备份。原站需先具备同等的私有导出接口；不要使用初始资料替代原站已修改的内容、草稿或账号。
4. 停止发布操作后，将完整备份恢复到新建的数据目录，验证数量、图片、账号登录和最近版本，再启动新站。恢复命令：`node scripts/restore-store.mjs 私有备份.json 全新的数据目录`。不能覆盖已有数据库。
5. GUIDE_DATA_DIR 必须指向绝对路径的持久目录；Docker 中已设为 `/data`。SITE_URL 必须是最终 HTTPS 地址，确保反向代理后的登录和编辑正常。
6. 资料迁移和网络验收通过后再交付新分享链接。原站保留为回退，不能提前删除。

源码包不包含原站已创建的管理员账号或任何真实密码。实际迁移使用另行保护的完整备份，切换后原密码登录应通过实测。

## 日常维护

进入 `/admin` 登录。编辑 → 保存草稿 → 预览 → 填写更新说明 → 发布。同学刷新或重新打开后读取最新版本。主管理员可登录后访问 `/api/admin/export` 下载备份；该文件含账号登录资料，请私下保存。

重新部署应用保留数据卷。不要执行删除数据卷的操作，也不要把备份、`.env` 或数据库提交到代码仓库。
